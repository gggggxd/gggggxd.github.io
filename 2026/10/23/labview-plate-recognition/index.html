LabVIEW车牌识别

忘川

用 LabVIEW 2020 + NI Vision Assistant 2020 做一套车牌识别。输入是手机摄像头的实时画面，输出是车牌字符串。整套流程分三段：采集、定位、识别。定位这一段的难点在新能源绿牌——它的底色是从白到绿的渐变，单一颜色阈值切不出完整车牌。下面按技术路线逐段说明。

一、整体结构

主程序 main.vi 用一个 While 循环跑整个流程，三个模块各自封装成独立 VI：

模块 实现 作用
图像采集 IMAQdx + IP Camera Adapter 手机 MJPEG 流 → LabVIEW 图像
车牌定位 subvi蓝色车牌提取.vi、subvi绿色车牌提取.vi 颜色分割 + 形态学 + 形状匹配 → 车牌 ROI
字符识别 IMAQ OCR ROI → 车牌字符串

前面板只保留必要的输入：摄像头选择、写盘路径、输出图像尺寸（X/Y Resolution）、确定与停止按钮。蓝色车牌、绿色车牌两个指示灯显示识别出的是哪一类。主程序有两种工作模式：拍照模式抓一帧写入 File Path 2 再读回来识别，调试模式直接读该路径下的图片。两条支路走同一条读取路径，输入侧完全一致。

二、图像采集

没有工业相机，用手机当网络摄像头。

手机端跑 IP 摄像头 App，起 MJPEG 服务，界面会显示当前局域网的 IP 和端口（如 http://192.168.82.211:8081/）。电脑端用 Configure IP Camera Adapter 把这个地址注册成虚拟摄像头：

连接建立后，MAX 的设备与接口里会出现一个 MJPEG Camera "cam3"。对 IMAQdx 来说这就是一台普通相机，后面的 Open Camera → Configure Grab → Grab2 流程不需要任何改动。

Grab2 拿到一帧后按 JPEG 格式写入文件，主循环用 等待(ms) 控制取帧间隔，避免把网络缓冲抽空。

三、车牌定位

方案选择

定位环节比较过三种做法：

  • 边缘检测（Sobel、Roberts、Canny）：复杂背景下保险杠、装饰条也会产生大量边缘，车牌区域淹没在冗余信息里。
  • 霍夫变换：直线检测能力强，但后备箱、保险杠同样是矩形结构，误检率高，计算量也大。
  • HSL 颜色空间提取：车牌底色饱和度高、周围环境饱和度低，在 HSL 空间里容易分离；计算量小，适合实时处理。

最终选 HSL，并针对绿牌做了单独处理。

蓝牌：阈值分割 + 形状匹配

蓝牌底色单一，整块都能用阈值提取。流程是：

先填充孔洞再去小干扰，是为了避免车牌本身因字符或反光断裂时被当成小颗粒删掉。

阈值分割后仍然会剩下蓝色反光、蓝色车身一类的干扰块。这些区域大多不是矩形，所以用 IVA Shape Match 2 配一张蓝牌模板（blue_moban.png，151×51 的灰度图）做形状匹配，返回每个候选的匹配分数。

筛选策略很直接：分数超过阈值的候选里，只有一个就取它，有多个就取分数最高的那个。定出 ROI 后在原图上裁剪，得到车牌图像：

绿牌：取下半段，按比例补全

绿牌底色从白渐变到绿，单一阈值只能提取出下半部分。这一点反过来成了判别依据：蓝牌的形状匹配失败，就按绿牌处理。

绿牌走的链路和蓝牌基本一致——阈值、形态学、凸包、形状匹配——但匹配只能命中下半段：

拿到下半段之后利用渐变的方向性补全。渐变是由上往下的，横向颜色一致，所以下半段掩码的底边就是整块车牌的底边，掩码的宽度就是车牌的长边像素长度。车牌尺寸是国标固定的，长宽比已知，于是：

代码里这段是纯算术节点：从 IMAQ Particle Analysis 取出外接矩形的宽高，经 簇至数组转换、索引数组 拿到宽度，除 得高度，减 得顶边坐标。绿牌子 VI 里还保留了 IMAQ ColorMatch，在最后做一次颜色一致性校验，防止把其他绿色物块当成车牌。

两条链路的差异

蓝牌 绿牌
分割依据 整块 HSL 阈值 仅高饱和度下半段
定位手段 形状匹配 + 分数 尺寸比例反推
关键节点 IVA Shape Match 2 IMAQ Particle Analysis
判别方式 匹配成功即为蓝牌 蓝牌匹配失败即为绿牌

四、统一尺寸与灰度

两种车牌进 OCR 之前要先统一成同一种图像。

第一件事是算子的尺度问题。不同距离拍到的车牌像素尺寸差别很大，OCR 对字符大小敏感，所以先统一缩放到 200×50 像素：

第二件事是灰度。OCR 的训练集都是灰度图，但直接从 RGB 转灰度会丢掉车牌的对比度。实际测试下来，只取 RGB 中的绿色通道（IMAQ ExtractSingleColorPlane）能最大程度保留车牌原有颜色的对比关系：

  • 绿牌：底色是绿，绿色通道值高；字符是黑，值低 → 深色字、浅色底。
  • 蓝牌：底色是蓝，绿色通道值低；字符是白，值高 → 浅色字、深色底。

两者的明暗关系刚好相反。把蓝牌整体反色，两种车牌就变成同一形态——都是深色字、浅色底，OCR 只需要一套参数。

五、OCR

OCR 用 NI Vision Assistant 的 OCR 模块，代码由 Vision Assistant 直接生成 VI。

字符集训练

通用 OCR 模型对车牌字体的识别率不够，需要自己训练字符集。训练库按类别组织：24 个字母类共 144 个样本、27 个省份汉字类共 162 个样本、60 个数字样本，训练结果保存为 temp_super_max.abc，运行时和 VI 一起加载。

属性设为 Dark on Light（深色字、浅色底），和上一节反色后的图像一致：

字符分割参数

Vision Assistant 的字符分割由六个参数控制：① 字符宽度、② 字符高度、③ 最小字符间距、④⑤⑥ 像素间距参数。前三个决定分割效果。

实测车牌字符宽度 10–20 像素、高度约 35 像素、字符间距约 6 像素，据此把范围放宽以避开铆钉等干扰：

  • 宽度 10–25 像素
  • 高度 20–40 像素
  • 最小间距 4 像素

自定义 ROI

OCR 只识别 ROI 内的区域，框选范围直接决定识别结果，所以要自己定义 ROI 结构。ROI 由四部分组成：

  • Global Rectangle：选框的绝对坐标，左上和右下两点
  • ID：取框内或框外
  • Type：选框类型，这里用矩形
  • Coordinates：框内的相对坐标

把 Global Rectangle 和 Coordinates 设成相同值，ID 选框内、Type 选矩形，就等价于整幅图全选。这样识别范围严格限制在定位模块给出的车牌区域内。

六、测试结果

测试地点在宁波大学北区杨咏曼楼周边四个片区，时间下午 1:30–2:30。手机与电脑连同一网络，一人持手机对准车牌，一人操作电脑按确认，一人录像佐证。同一块车牌只统计第一次按确认的结果。

共 81 块车牌、580 个字符：

指标 全部 蓝牌 绿牌
车牌样本 81 68 13
字符样本 580 476 104
框选准确率 100% 100% 100%
完整识别率 72.84%（59/81） 76.47%（52/68） 53.85%（7/13）
字符识别率 93.45%（542/580） 93.28%（444/476） 94.23%（98/104）

框选准确率 100%，说明 HSL 定位这条路在测试条件下是稳的。

字符识别率和完整识别率差了 20 个百分点，原因在字符数。蓝牌 7 位，绿牌 8 位，整牌全对要求每一位都对：

蓝牌实测 76.47%，高于理论值。同一块车牌的字体、光照、清晰度是共享的，识别结果正相关，不是独立事件。绿牌实测 53.85%，低于理论值，主要原因是样本只有 13 块，一两块失手就会明显拉低比率。

七、适用范围

这套方法依赖两个前提：光照充足、拍摄角度接近正面。测试全部在下午晴天进行，夜间、逆光、大角度倾斜没有覆盖。绿牌样本 13 块，且集中在同一时段同一区域，53.85% 这个数字的置信区间很宽。

继续往下做的话，有三个方向：用霍夫变换做倾斜校正，把倾斜车牌拉正再识别；用灰度直方图找双峰动态设定二值化阈值，处理积灰或饱和度偏低的车牌；扩充不同光照条件下的训练样本。
