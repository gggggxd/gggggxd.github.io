简介

把一台移动双臂机器人推进一栋没见过的房子，关上门，只说一句 clean the kitchen。接下来一段时间，它要自己判断先关哪扇柜门、台面上哪些东西该收进抽屉、盘子该放进水槽还是沥水架。

1. 动机

π0.5 沿用 π0 的 PaliGemma 2B 加 action expert 骨架，把机器人真正放进真实家庭，想解决的是 π0 泛化能力不足 的问题。

π0 在训练过的环境里能完成任务，但换一间没见过的厨房，表现就明显下降。论文把原因拆成三个瓶颈：

  • 数据覆盖：不可能在每个厨房都采一遍数据。论文原话是 “brute-force scaling of robot data collection is infeasible”。π0.5 的移动机器人数据只有 约 400 小时、约 100 个家庭，在预训练样本里占 约 2.4%；其余 97.6% 来自别的机器人、实验室数据、网页图文和子任务标注。人话指令（VI）不在预训练阶段，只在后训练加入。
  • 长程语义：10 到 15 分钟的任务包含多个子步骤，“该开哪个抽屉”“盘子放进水槽还是沥水架”靠的是常识，不是动作技能。机器人数据里几乎没有，网页图文和语言标注里有。
  • 低层连续动作：机器人以 50 Hz 执行，一个动作块覆盖 1 秒；若把 50 步 × 18–19 维的动作块离散成 FAST token 后自回归解码，延迟仍难以满足 20 ms 的控制周期。这是 π0 和 π0.5 都用 flow matching 的原因。

针对这三个瓶颈，作者在预训练阶段将机器人操作、网页图文和子任务标注等数据转成模型可处理的多模态序列共同训练；后训练再加入 VI，并用 flow matching 学习连续动作。分层推理则把长程任务分解与低层控制衔接起来。

2. 数据

2.1 六类数据

π0.5 的数据配方由六类来源组成，规模、目标和占比见表 1。

论文只单列了 MM 占预训练样本约 2.4%、ME/CE/HL/WD 四项合计约 97.6%；四者的单独占比没有给出。VI 只在后训练加入，11% 是占高层移动操作样本，不是占预训练总量。表中的 CE 是跨本体数据类别；HL 是高层子任务数据。

不同数据类型的样本量差异很大，作者为了平衡采样，π0 论文在 task–robot 组合层面，按每个组合的样本数 n_i 使用权重 w_i = n_i^0.43，再归一化为采样概率 p_i = w_i / Σ_j w_j。指数小于 1 会压平大、小组合之间的权重差距：大组合仍有更高采样概率，但小组合获得了更高的相对采样机会。

这里的 n_i 是第 i 个 task–robot 组合的样本数，不是表 1 中某一类数据的占比。π0.5 论文没有重复 π0 的 0.43 指数，也没有公开每个组合的 n_i，所以无法从表 1 直接算出“加权后 MM/ME/CE/HL/WD 各占多少”。能确定的是重加权的方向：样本量相差 10 倍，权重比变成 10^0.43 ≈ 2.69 倍；相差 1000 倍变成约 19.5 倍；相差 10000 倍变成约 52.5 倍。

下面用 5 个假想的组合演示公式的完整算法（数字只为说明机制，不是论文原始统计）：

task–robot 组合 原始样本数 n_i 原始占比 w_i = n_i^0.43 加权后 p_i 相对变化
A 1,000,000 90.0% 380.2 63.3% 0.70×
B 100,000 9.0% 141.3 23.5% 2.61×
C 10,000 0.9% 52.5 8.7% 9.7×
D 1,000 0.09% 19.5 3.3% 36×

示意：p_i = w_i / Σ_j w_j。最大组合的原始占比 90% 被压到 63%，最小组合从 0.009% 提到 1.2%；排序不变，但差距明显收窄。

后训练阶段去掉 CE、加入 VI：CE 是实验室跨本体数据，与目标域差异较大；VI 的占比虽小，但能补充子任务语言示范。低层监督仍主要来自 MM/ME 中成功且长度合适的 episode，WD 保留语义/视觉能力，HL 的 multi-environment 切片继续供高层使用。

图 2：预训练用 MM、ME、CE、HL、WD，后训练加上 VI 并去掉 CE。图源：π0.5 论文 Fig. 4。

预训练时，不同模态以不同表示进入共享的序列建模框架：图像经视觉编码器形成视觉 token；文本、物体框标签和 FAST 离散动作作为交叉熵预测目标。后训练时，连续动作由 action expert 通过 flow matching 学习，文本与子任务仍走交叉熵。统一的是序列建模框架，不是同一种 tokenizer 或损失。

2.2 泛化证据：从真实家庭到消融

这一节按“真实家庭 → 位置数扩展 → 语言跟随 → 数据消融 → 模型对比 → 高层消融”的顺序，先给结论和量级；机制细节在后面几节展开。

这里的 task progress 是论文用来衡量任务完成程度的连续指标，百分比不能直接当作一次 episode 的成功率；第 5 节 LIBERO 报告的 done 则是二元成功判据。汇报时应把这两类数字分开读。

真实家庭：先看主结果。 论文在 3 个未参与训练的厨房和 3 个卧室里评测，任务是 items in drawer、laundry basket、dishes in sink。每个任务只给一句高层指令，模型自己拆子任务；Fig. 7 左侧是 Home 1/2/3 的 rollout，右侧给出每个任务的 task progress。真实家庭与 mock environments 的量级接近，说明后面的 mock home 消融不是只在玩具环境里成立。

图 3：真实家庭与 mock home 的 task progress。左侧是 Home 1/2/3 的 rollout 和 high-level 子任务预测，右侧是逐任务 task progress。图源：π0.5 论文 Fig. 7。

位置数（locations）：数据覆盖是第一道门槛。 论文按 3、12、22、53、82、104 个训练位置递增；四个任务的平均 task progress 从约 14% 升到约 86%。直接在测试家庭上训练的 in-domain 对照约 82%，104 个训练位置的完整模型已经接近这个数。若去掉共训预训练，104 个训练位置只剩约 4%；而在测试家庭上训练但去掉共训预训练约 39%，仍明显低于完整配方。

图 4：训练位置数从 3 到 104，平均 progress 从约 14% 到约 86%；绿色柱是直接在测试家庭上训练的 in-domain 对照（约 82%），浅黄柱是 104 个位置但不做共训预训练（约 4%）。图源：π0.5 论文 Fig. 8。

语言跟随：WD 对 OOD 物体尤其重要。 论文让机器人在厨房台面上按语言指令取指定物体，分 in-distribution（训练中见过的类别、新实例）和 OOD（未见过的类别），同时报告 follow rate 和 success rate。Fig. 9 显示，随着训练位置数增加，两项指标都上升，in-distribution 上升更快；Fig. 11 的消融显示，去掉 WD 对 OOD 掉点最大（OOD follow rate 约 93%→67%，success 约 93%→73%），去掉 CE/ME 对 in-distribution 和 OOD 都明显掉点。这解释了为什么 WD 在 mock home 的主任务上不显著，却仍是配方的一部分。

图 5：语言跟随率与成功率随训练位置数的变化。灰线是 in-distribution 物体，黄线是 OOD 物体。图源：π0.5 论文 Fig. 9。

配方消融：异构数据缺一不可。 去掉 CE 数据或 ME 数据都显著掉点：只去掉 CE 约 51%，只去掉 ME 约 53%，两个都去掉约 41%，都低于完整模型约 78%（p<0.001）。去掉 WD 数据在 mock home 上不显著（约 72%，p=0.385），但后面的高层消融会看到它的作用。

图 6：去掉 CE 数据或 ME 数据显著掉点，去掉 WD 数据在 mock home 上不显著。图源：π0.5 论文 Fig. 10。

模型对比：π0.5 明显优于 π0。 四任务平均，π0.5 约 78%，π0-FAST+Flow 约 60%，π0 训到 300k 步约 31%。π0-FAST+Flow 是 π0 的变体：用 FAST 把动作离散成 token、与文本一起做自回归预训练，再加 flow matching 头，但推理时不做高层推理。

图 7：π0.5 平均约 78%，π0-FAST+Flow 约 60%，π0 训到 300k 步约 31%。图源：π0.5 论文 Fig. 12。

高层消融：显式高层最好，隐式高层也能学到。 完整模型在运行时显式生成子任务；implicit high-level（隐式高层）不做运行时的高层推理，但训练时见过高层数据，让模型隐式学到子任务。Fig. 13 的主要结论是：

  • 完整模型（显式高层）：最好（约 78%），甚至超过人工提供的高层子任务序列（human oracle，约 64%）；
  • 隐式高层：第二（约 70%）；
  • human HL oracle：约 64%，低于完整模型，也低于隐式高层；
  • no HL（训练时也不使用高层数据）：约 62%，明显低于隐式高层；
  • no VI（去掉口头指令数据）：约 60%，显著变差（p=0.009）；VI 只占高层移动操作样本约 11%；
  • no WD（去掉网页图文数据）：约 60%，显著变差（p=0.008）；
  • GPT-4 zero-shot：最差（约 58%）。

图 8：高层推理消融的完整结果。图源：π0.5 论文 Fig. 13。

3. 架构

3.1 整体架构：一个 VLM，两阶段训练

π0.5 沿用 π0 的 PaliGemma VLM + action expert 骨架，但把同一个模型拆成高层和低层两种用法：同一个 VLM 在高层模式下自回归生成子任务；在低层模式下，它作为 prefix 编码器，与 action expert 一起生成连续动作。高层与低层共享同一套 VLM 权重，差别只在是否接入 action expert，以及输入输出的形式。两阶段训练把这两种能力接起来：

  • 预训练（只训 VLM）：语言、物体框和 FAST 离散动作都写成 token，统一做 next-token prediction。这个 VLM 之后同时充当高层策略和低层的 prefix 编码器。
  • 后训练（高层 + 低层）：接入 action expert，动作目标换成 flow matching；高层仍由 VLM 生成子任务，低层由 VLM + action expert 生成动作，同时保留文本/子任务的交叉熵。

3.2 高层模型

高层模型就是 VLM 本身：预训练时，它学习统一的 token 预测；推理时，它只负责生成子任务。

预训练：先把 VLM 训成统一 token 预测器。 预训练阶段还没有 action expert，模型就是一个 PaliGemma VLM。图像先经 SigLIP 编码成每路 256 个 token：输入为 224×224，patch 为 14×14，共 16×16 个 patch；在四路相机的移动平台配置下，合计 1024 个图像 token。输入还包括任务 prompt；π0.5 默认把 state 离散成数字串，一并放进 prompt。输出可以是文本、物体框坐标或 FAST 动作 token，三者共用同一个 next-token 交叉熵目标。FAST 把动作块压缩成离散 token，动作预测因此被改写成语言模型式的序列预测。

图 9a（预训练放大）：语言子任务、离散动作、caption、bounding box 都作为 next-token 预测目标；此时没有 action expert。图源：π0.5 论文 Fig. 3。

高层推理：只启用 VLM。 输入是 4 路相机（前向、后向、左右腕）、高层任务指令，以及默认配置下的离散 state token；输出是一段短子任务文本：

高层与低层共用同一套 VLM 权重，差别在 prompt、相机数量以及是否接入 action expert。高层输出会作为低层的 prompt，因此 pick up the pillow 既是高层的生成结果，也是低层动作的条件。高层以较低频率更新子任务；子任务不变时，低层连续执行动作块。

PaliGemma 处理 prefix，action expert 处理 suffix。prefix 的 K/V 由 VLM 计算，每次推理只 prefill 一次并缓存，在后续去噪迭代中复用；suffix 的 K/V 则在每次去噪迭代中重新计算。动作维度在配置里统一补零到 32 维；动作块由 flow matching 从噪声去噪得到，细节见 §3.5。

图 11：左图按层号展开 18 层，每个 Block_i 同时包含 PaliGemma_i 与 ActionExpert_i；中图是 prefix/suffix 穿过 18 层共享栈的信息流；右图放大 Block_i，列出两套 Q/K/V/O、FFN 的维度与参数分工。底部对比训练、prefix prefill 和 suffix 去噪。维度按 openpi 配置。自制图。

内部结构。 把 PaliGemma 和 action expert 拆开看，内部是一个 18 层共享 Transformer：每层中，两者各有一套投影、归一化和 FFN，但 K/V 拼接后只做一次 attention。代码里 Module 堆叠 18 个 Block，每个 Block_i 同时包含 PaliGemma_i 和 ActionExpert_i 两套子层；两者各自做 Norm、Q/K/V、O 投影和 FFN。推理时，ActionExpert_i 读取 PaliGemma_i 缓存的 prefix K/V。

训练时，每层对两组 token 分别做 norm（prefix 用普通 RMSNorm，suffix 用 adaRMSNorm 注入时间），再各自投影 Q/K/V。推理时只计算当前激活的一组，投影和拼接规则相同。Attention.__call__ 中，每个 expert 用自己的 q_einsum / kv_einsum 计算 q/k/v，然后沿 token 轴拼接：

  • BTD：batch、query 长度、宽度；NDH：query head 数、宽度、head_dim；BSKH：batch、KV 长度、KV head 数、head_dim。
  • qkvs 是一个列表，每个 expert 对应一项。zip(*qkvs) 把两个 expert 的 q、k、v 分别取出，jnp.concatenate(..., axis=1) 沿 token 轴拼接。拼接后只做一次 softmax，两个 expert 的 token 落在同一个注意力矩阵中，可见性由 mask 决定。
  • Q 不共享：每个 expert 用自己的 q_einsum；K/V 也不共享权重：各自计算后再拼接。所谓“共享 attention”，指共享一次注意力计算，不共享投影权重。
  • attention 输出按 token 范围切回，每个 expert 用自己的 attn_vec_einsum 做输出投影。PaliGemma 与 action expert 只在联合 attention 中交互：Q/K/V 沿 token 轴拼接后做一次 softmax，投影权重仍各自独立。

3.4 注意力 mask：prefix、suffix 与 FAST token

为了让预训练和后训练共用一套序列格式而不互相干扰，作者用 attention mask 控制三组 token 的可见性：prefix、FAST 动作 token 和连续动作 token。高层文本生成使用普通的因果 mask：prefix 内全可见，生成出的文本 token 只能看 prefix 和之前的文本 token。低层连续动作则需要看到整个 prefix 和动作块内部，但不能看到 FAST token，以免两种动作表示互相泄漏。

make_attn_mask 的核心逻辑只有几行：

  • action_horizon=10 让模型一次只预测 10 步，不是 π0 默认的 50。
  • discrete_state_input=False 不将 state 写入 prompt；pi05=True 又使 suffix 不建立 state token，因此模型不使用 state。

反直觉点：LIBERO 复现不读 state，也不用右腕相机。 客户端仍会拼 8 维 state 并送进 Normalize，但 discrete_state_input=False 加上 pi05=True 的 suffix 无 state token，模型实际只看到 2 路真实图像（base + left wrist）和任务文本；right_wrist_0_rgb 是零图且 image_mask=False。所以后面的 LIBERO 数字应理解为“vision-language only”的低层策略结果，不是论文默认的 3 相机 + state 配置。

数据侧，prompt_from_task=True 使用数据集任务名；extra_delta_transform=False 保留 LIBERO 已经是 delta 的动作（见 §4.1）。

服务端每个连接串行处理，没有请求队列，也没有超时；第一次调用会包含 JAX 的 JIT 编译时间，后面的调用才是稳定延迟。

5.3 LIBERO 客户端

评测分为服务端推理和客户端仿真两部分，完整 episode 循环见图 17。

图 17：单局控制时序。动作队列耗尽时请求服务端，缓存预测动作的前 5 步；到 done 或 max_steps 时结束本局；图中底部按 2,000 局全量汇总。自制图。

每局从 env.set_init_state 开始，先执行 10 步 dummy action 等物体落稳；这段等待不计入策略步数。

之后每个控制步做四件事：旋转图像、拼 state、需要时请求、执行一个动作；一局到 done 或 max_steps 结束。

LIBERO 图像需先旋转 180° 再 resize 到 224，以匹配训练预处理；漏掉旋转会让策略看到反向图像。

客户端 state 按末端位置 3 维、轴角 3 维、夹爪 2 维拼成 8 维；LiberoInputs 和 Normalize 要求这个形状与顺序。模型侧不读 state（见 §5.2 的 callout），这一步只是保持接口一致。

动作块如何还原。 服务端返回前，Policy.infer 已完成输出变换：18 层 suffix 输出 [B, H, 1024]，action_out_proj 投到 [B, H, 32]；Unnormalize 把 [-1, 1] 还原到原始量纲，LiberoOutputs 再切回 7 维（ALOHA 14 维、DROID 8 维）。客户端拿到的 actions 已是可执行维度，按行读取即可。

动作队列为空时请求 [10, 7] 动作块，将前 5 步放入 deque 逐步执行；执行完后再请求下一块。

每次预测执行多少步。 上面只取前 5 步不是随手截断，而是按执行 horizon 主动丢弃后半段。各示例的配置不同：

5.5 局限与讨论

论文自己列了三类失败：不熟悉的抽屉把手或物理上难开的柜门；部分可观测（例如机械臂挡住要擦的污渍）；高层子任务容易被分散（放东西时反复开关抽屉）。方法层面的限制是 prompt 还比较简单、context 和 memory 有限，跨房间导航或记住物体位置这类任务还不够；预训练数据和配方没有开源，openpi 只提供后训练 checkpoint 和低层推理接口。

对本次复现而言，LIBERO 评测是 low-level、vision-language only 的仿真结果：它验证了 checkpoint、数据预处理、动作块执行和评测链路，但不能替代论文的真实家庭实验，也没有覆盖高层子任务生成。下一步如果要继续，可以优先补三件事：用 pi05_base 在真实/仿真数据上做高层子任务微调；把 state 重新接回低层（优先试 discrete_state_input=True；若要 π0 式的连续 state token，则改 embed_suffix）；在 LIBERO 之外加一个长程、多阶段的评测。
